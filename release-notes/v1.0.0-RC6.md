# Albumio v1.0.0-RC6

第六个候选版本。本版只做一件事：**修掉 RC5 打开即卡死（窗口无响应）的阻断问题**，其余功能与 RC5 相同。

## 阻断问题与根因

- **现象**：RC5 的 Windows 安装包打开后窗口直接「未响应」，单核 CPU 100%，完全不可用。
- **取证**：装包进程 `Responding=False`，子进程已有 `msedgewebview2.exe`（WebView2 正常启动，不是白屏/未起来）；线程快照里只有一个线程 Running 且吃满一个核，其余全部 Wait，无 panic。同一份代码用 `tauri dev` 也能复现，说明是 Rust 主线程被同步命令占死。
- **定位**：启动后 `albumio_list` 进入 `read_images`，readdir 1 ms 就返回，随后卡在 `sort_by`——自然序比较器 `natural_cmp` 死循环。
- **根因**：比较器混用了两种偏移。`a[anext..].char_indices()` 给出的是「切片内相对偏移」，却被当成「整串绝对偏移」传给 `take_digits`。数字段消费之后取到的字符错位、偏移不再前进，比较器永不返回。
- **触发条件**：目录里存在「共同前缀 + 两段数字」的文件名，例如 `Snipaste_2025-03-09_12-45-53.png` 与 `Snipaste_2025-03-20_21-28-43.png`（截图、相机导出基本都是这种命名）。本机「图片」目录里这类文件名有 7001 对。
- **影响面**：**三平台**，不是 Windows 特有。启动不带参数时前端会回退到系统「图片」目录（`app/src/data/source.ts` 的 `launchTarget`），只要该目录里有这类文件名，启动即卡死。
- **来源**：该比较器自 M2（`c94cbd5`）起就存在，与 RC5 新增的单实例、剪贴板粘贴、目录监听、自绘标题栏、`capabilities/default.json` 无关——这些在卡死前都已正常返回。

## 本版修复

- `albumio-core` 的 `natural_cmp` 重写为两侧统一用「整串绝对字节偏移」推进，数字段等值也必须各前进至少一个字符；名字里的数字段仍按数值比较（`DSC_2` 在 `DSC_10` 前），前导零（`IMG_01` 与 `IMG_1`）视作相等。
- 补回归测试 `natural_cmp_terminates_on_two_digit_runs`，覆盖上述截图/相机命名与前导零两种情形。

## 本版验证

- `cargo test -p albumio-core`：8 passed（含新增回归用例）。
- `tauri dev` 复验：`readdir 433 条 1 ms` → 排序完成 → `albumio_list` 返回 354 个图片条目 1 ms，窗口 `Responding=True`，CPU 平稳。
- `tauri build --no-bundle` 产出的 release 包（前端内嵌）在 Windows 上启动后 `Responding=True`、CPU 稳定在 1 s 内、WebView2 子进程正常。
- 对照：RC5 安装包在本机仍可复现卡死（`Responding=False`、单核 100%），差异只来自本次提交。

## 已知限制（与 RC5 相同）

- 安装包**未做代码签名与 Apple 公证**：Windows SmartScreen 与 macOS Gatekeeper 会提示「未知开发者」，macOS 需在「系统设置 → 隐私与安全性」里手动允许；dmg 未公证。
- Win11 右键菜单需要签名后的 MSIX 才能 `Add-AppxPackage` 注册，本版安装包暂未携带 `AlbumioShell.dll`。
- AVIF / RAW 仍未接入解码，调用会返回明确的 Unsupported。
- 单实例、剪贴板、右键菜单与 macOS/Linux 的 HEIC 解码只过了编译与本地构建，尚未做真机交互验证。
- Linux 自动更新只使用 AppImage；deb 为手动下载项。

## 校验方式

- 每个安装包都附 `.sig`（minisign），可用应用内嵌公钥校验；`latest.json` 含三平台更新条目。
- `SHA256SUMS` 覆盖全部附件（含 `.sig`），下载后可用 `sha256sum -c` 逐条核对。
