# Albumio v1.0.0-RC7

第七个候选版本。功能与 RC6 相同（含 RC6 修掉的「打开即卡死」），本版只做一件事：**产品显示名从小写 `albumio` 改为 `Albumio`**。

## 本版变更

- 用户可见的应用名统一为 `Albumio`：安装程序、开始菜单 / 桌面快捷方式、应用与功能列表、窗口标题、macOS 访达与 Dock、Linux 桌面菜单。
- **下载得到的文件名一个都没变**：仍是 `albumio_1.0.0-RC7_x64-setup.exe`、`albumio_1.0.0-RC7_x64_en-US.msi`、`albumio_1.0.0-RC7_universal.dmg`、`albumio_1.0.0-RC7_amd64.AppImage`、`albumio_1.0.0-RC7_amd64.deb`、`albumio.app.tar.gz`；`latest.json` 里的资产名与下载地址、`SHA256SUMS` 全部沿用原来的小写命名。
- 内部标识一个都没动：包标识 `com.albumio.app`、Rust crate 与 npm 包名、`albumio_*` 命令 / 事件名、数据目录 `%APPDATA%\albumio`（升级后图库缓存与设置原地保留）。

### 显示名与文件名是怎么解耦的

Tauri 的 `productName` 同时决定「系统显示名」和「产物文件名」，没有独立的显示名字段可用。本版的处理是：

- `productName` 设为 `Albumio`，让系统各处显示大写；
- 显式 `mainBinaryName: "albumio"`，保住可执行文件名仍是 `albumio.exe`（便携构建脚本、开机自启路径、已有快捷方式目标都不受影响）；
- 发版流水线在展平产物后、签名前执行 `scripts/rename-artifacts.mjs`，把 `Albumio_*` 前缀改回 `albumio_*`，签名因此也落在小写名上。

## 各平台实际表现

### Windows

- 安装程序标题、「应用和功能」里的条目、开始菜单与桌面快捷方式均为 `Albumio`。
- 安装目录为 `%LOCALAPPDATA%\Albumio`（默认每用户安装），可执行文件在 `%LOCALAPPDATA%\Albumio\albumio.exe`——目录名变了，exe 名没变。
- MSI 的 ProductName 为 `Albumio`。WiX 的 UpgradeCode 默认由 `productName` 派生，本版没有固定它，因此 RC7 与本仓库此前的 Windows 版本会被系统视为两个独立应用（会各自出现在「应用和功能」里）。当前实际没有用户，按约定不做迁移兼容处理。
- 下载到的安装包文件名不变：`albumio_1.0.0-RC7_x64-setup.exe`、`albumio_1.0.0-RC7_x64_en-US.msi`。

### macOS

- 应用包为 `Albumio.app`，访达、Dock、菜单栏与「关于」显示 `Albumio`；`CFBundleIdentifier` 仍是 `com.albumio.app`。
- dmg 与更新包的文件名在发版时改写回小写：`albumio_1.0.0-RC7_universal.dmg`、`albumio.app.tar.gz`。
- 若机器上还留着旧的小写 `albumio.app`，改名后它会与 `Albumio.app` 并存。当前没有用户，不做清理提示。

### Linux

- 桌面菜单条目显示 `Albumio`，安装后的可执行文件仍是 `albumio`（`/usr/bin/albumio`），`desktop` 文件里的 `Exec` 也仍指向它。
- AppImage 与 deb 文件名不变：`albumio_1.0.0-RC7_amd64.AppImage`、`albumio_1.0.0-RC7_amd64.deb`。
- 自动更新仍然只走 AppImage；deb 为手动下载项。

## 本版验证

- `tauri build --no-bundle`（含新版配置）输出仍为 `target/release/albumio.exe`，说明 `mainBinaryName` 生效、二进制名没有被 `productName` 带走。
- `scripts/rename-artifacts.mjs` 用八种真实产物名（nsis exe / exe.sig / msi / dmg / app.tar.gz / app.tar.gz.sig / deb / AppImage）跑通：全部改名为小写，非产物文件不动，重复执行改名数为 0（幂等），目标名已真实存在时拒绝覆盖并退出 1。
- 发版流水线新增的改名步骤位于「展平产物目录」之后、「补齐未签名的安装包」之前，签名与 `latest.json` 生成因此看到的都是小写名。
- 出包后在本机用 `scripts/smoke-windows.ps1` 对安装后的进程复验：窗口 `Responding=True`、缩略图目录有新增产出。

## 已知限制（与 RC6 相同）

- 安装包**未做代码签名与 Apple 公证**：Windows SmartScreen 与 macOS Gatekeeper 会提示「未知开发者」，macOS 需在「系统设置 → 隐私与安全性」里手动允许；dmg 未公证。
- Win11 右键菜单需要签名后的 MSIX 才能 `Add-AppxPackage` 注册，本版安装包暂未携带 `AlbumioShell.dll`。
- AVIF / RAW 仍未接入解码，调用会返回明确的 Unsupported。
- 单实例、剪贴板、右键菜单与 macOS/Linux 的 HEIC 解码只过了编译与本地构建，尚未做真机交互验证。

## 校验方式

- 每个安装包都附 `.sig`（minisign），可用应用内嵌公钥校验；`latest.json` 含三平台更新条目。
- `SHA256SUMS` 覆盖全部附件（含 `.sig`），下载后可用 `sha256sum -c` 逐条核对。
