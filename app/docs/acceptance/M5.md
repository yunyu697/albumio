## 2. 验收标准逐条证据

### 2.1 三种格式打开耗时

后端 `Level::L2` 生成（release，单机，冷缓存 → 再打开命中），命令：`cargo run --release -p albumio-core --example m5bench -- <files>`（本轮为临时测例，跑完已删）。

| 样本 | 尺寸 | L2 产物 | 冷生成 | 二次打开（磁盘缓存命中） |
| --- | --- | --- | --- | --- |
| `big-4000x3000.jpg`（3.5 MB） | 4000×3000 | 2048×1536 · 29 KB | 936 ms | 1.08 ms |
| 生成 PNG（4000×3000） | 4000×3000 | 2048×1536 · 88 KB | 802 ms | 1.57 ms |
| `example.heic`（701 KB，libheif 样例） | 1280×854 | 1280×854 · 266 KB | 483 ms | 1.17 ms |

结论与边界：

- 冷路径的成本在「完整解码 + Lanczos 重采样到 2048 + WebP 编码 + 落盘」，与格式无关；二次打开只剩读文件。
- viewer 首帧不等 L2：先用网格里已有的 **L1** 贴上（通常已解码），L2 到了再替换，因此「打开白屏」不会被 L2 冷生成拖住。
- **不构成 `01-方案文档` §3.4 的达标证明**：样本不是 50 MB JPEG / 24 MP HEIC / 60 MB PNG，且该表要求 bench 脚本口径。按 220 ms 首屏目标，冷 L2 的 936 ms 是明确缺口，见 §5。

### 2.2 400% 不糊（源是 L2，不是 L1）

`m5-check` 第 4 步：

- `Z` 实际像素：`pct = 100%`，`img.naturalWidth = 2048`，CSS 宽 `2048`（1 L2 px = 1 CSS px）。
- 连按 7 档 `+`：`pct = 477%`，`naturalWidth` 仍为 `2048`，CSS 宽 `9765.63`。
- `F` 适应：`pct = 54%`，CSS 宽 `1110.27`（= 2048 × 0.542，舞台 1376×740 下按高贴合）。

即 400% 以上看到的是 L2 的真实像素被放大，源没有退回 256 px 的 L1。

### 2.3 翻页 0 白屏

`m5-check` 第 3 步连按 8 次 `→`，每步 90 ms 后采样：

- 每步 `imgCount = 1`、`complete = true`、`naturalWidth = 2048`；
- 计数从 `1 / 42` 连续走到 `9 / 42`，没有出现无 `img` 或非 L2 的帧。

预取窗口为 ±1（`previewUrl` 预取，`heldRef` 只保留当前、前后各一与正在显示的那张），±2 只预热不保留。

## 4. G3 差异项（均有归属）

| 差异 | 原因 / 计划 |
| --- | --- |
| 适应窗口显示 54%，设计稿静态写 100% | 百分比按「100% = L2 1:1」定义（§10.3 的 Z 是实际像素）；设计稿是静态示意，未绑定真实图片尺寸。数值语义优先于示意文本 |
| 文件名/尺寸/计数与设计稿不同 | 截图用 mock 目录（42 项），设计稿是固定示例 |
| 信息浮层的「路径」一行可省略号截断 | 真实路径长度不可控；设计稿示例路径较短 |
| 编辑按钮不响应 | 编辑属 M6；按钮保留位置与提示，不伪造未实现的界面 |
| 胶片格提示用原生 `title` | `.film` 横向滚动必须 `overflow`，自定义 `.tip` 会被裁掉；按钮类仍有完整 `.tip` |

## 5. 已知限制与未达标项

1. **冷 L2 生成 802–936 ms**，高于 §3.4「首屏 ≤220 ms / 100% 可平移 ≤700 ms」的目标口径。当前用 L1 兜底首帧，但按 `Z` 真正 1:1 要等 L2。后续动作：给 `pipeline::thumbnail` 加阶段计时（decode / resize / encode / write）定位占比，再决定是否把 Lanczos 换成分块/双线性预降采样，或对 L2 也走 jpeg-decoder 的分数解码档位。
2. **HEIC 样本不是 24 MP**：本机只有 1280×854 的公开样例，没有 24 MP 真机 HEIC。`01-方案文档` §3.4 的 600 ms 目标未被验证。
3. **HEIC 的 ICC 与方向**：WIC 路径固定 `orientation = 1`，也不读 ICC（iPhone 的 Display P3 会按 sRGB 显示）。色彩校准与旋转写入随 M6/M7 的色彩与编辑里程碑处理。
4. **WIC 全尺寸解码**：峰值内存 ≈ 宽×高×4（25 MP 约 100 MB），没有分块解码；`§3.3 峰值 ≤700 MB` 在 1 亿像素全景上仍不成立（HEIC 路径）。
5. **AVIF / RAW 只做了同一入口**：WIC 有对应扩展时可用，未单独取样本验收，按 M5 范围（HEIC 必须能打开）不阻塞。
