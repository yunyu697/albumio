## 2. 验收标准逐条证据

### 2.1 100 张混合格式批量导出全部成功，命名无冲突、无覆盖

`tests/batch.rs::hundred_mixed_formats_all_succeed`：100 个来源（PNG / WebP / BMP / JPEG / TIFF 混合 97 张 + 两个不同目录同名 `dup.jpg` + 1 张损坏文件），模板 `{原名}_{序号}`、转 JPEG、长边 1280：

- 99 张 `done`、1 张 `failed`（损坏文件）；
- 99 个输出路径两两不同（`HashSet` 去重后仍为 99）；
- 任一输出路径都不等于任一源路径；
- 输出目录无 `.part` 残留。

`conflicts_get_suffix_and_never_overwrite`：两个同名来源得到 `same.jpg` / `same_1.jpg`，`plan.conflicts == 1`；再次规划时已存在的输出被避开（`same_2.jpg`），源文件字节不变。

### 2.2 失败逐条原因

- `corrupt_source_fails_with_reason_not_silence`：写入 `not an image at all` 的 `broken.jpg` → `status == "failed"`，原因包含「源文件不可读」。
- 原因按阶段区分：解码 → 源文件不可读；缩放/编码/写入各自带阶段前缀；单条失败不中断整批。

### 2.3 可中断：已完成文件有效、临时文件清理

`cancel_stops_at_file_boundary_and_cleans_parts`：5 张 4000×3000，首条结果一回来就置取消位：

- `outcome.cancelled == true`，`results.len() == 1`（不再启动下一条）；
- 已完成输出可解码且为 2048×1536；
- 输出目录无 `.part`；源图字节未变。

### 2.4 格式、尺寸与模板

- `convert_and_resize_outputs_real_files`：4000×3000 → 2048×1536；摘要含 `JPEG` 与 `长边 2048`；源图字节不变。
- `jpeg_output_embeds_srgb_and_resets_orientation`：orient-6 的 40×20 输出为 20×40（像素已转正），EXIF Orientation 为 1 或缺失，JPEG 内可找到 `ICC_PROFILE`。
- 单测 `template_expands_all_placeholders` / `unknown_placeholder_is_kept_verbatim` / `sanitize_handles_windows_limits` / `resize_never_upscales`。
- 前端 `npm run test:unit` 覆盖同名 `_1`、Windows 清洗、只缩不放、路径拼接。

## 3. 其余验收点

- 规划阶段不落盘：`plan()` 只读文件头/EXIF，输出名与尺寸一次算定，执行阶段不再决策。
- 输出目录默认 `<当前目录>\导出`，启动时自动创建；同名追加 `_1`、`_2`，不覆盖原图与既有文件。
- 进度：每条 `begin` / `item` 事件；界面按已完成条数计百分比，暂停后继续只跑未完成项。
- 模拟数据只在浏览器预览生效（`isTauri()` 为假），桌面端全部走 Rust。

## 4. 已知缺口

1. **添加入口**：设计稿顶栏右侧的「添加文件」未实现（需要引入 Tauri dialog 插件），当前来源为「已选 / 当前目录」；G3 对照时该位置为空。
2. **输出目录不可改**：设计稿为静态路径，本轮固定 `<目录>\导出`。
3. **ICC 只嵌入 JPEG**：PNG/WebP 输出像素已是 sRGB，但未写 iCCP/ICCP 块；JPEG 已带 profile。
4. **EXIF 只在 JPEG → JPEG 保留**：转 PNG/WebP 时不携带拍摄信息；JPEG 复制时仅改写 Orientation，未同步 PixelXDimension/YDimension。
5. **真实 GUI 手动验收未跑**：`cargo test`、`m7-check`（浏览器 mock）与构建均通过，但尚未在桌面窗口里对真实 100 张目录点一次「开始处理」。
6. **暂停语义**：暂停只在文件边界生效（单张大图解码期间会继续跑完），与计划的「可中断、已完成文件有效」一致，但不是逐字节中断。
