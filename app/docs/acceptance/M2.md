## 3. 性能实测

测试机：本机 NVMe SSD、Windows 11、WebView2、窗口 1440×900、DPR=1（隐藏滚动条）。

### 3.1 缩略图生成（release，抽样 60 张）

`cargo run --release -p albumio-core --example thumb_bench -- <1 万项目录> 60`

| 级别 | 单张 p50 | p95 | 串行吞吐 | 缓存命中 |
| --- | --- | --- | --- | --- |
| L0（32px） | 7 ms | 9 ms | 129.6 张/秒 | 0.67 ms |
| L1（256px） | 22 ms | 28 ms | 41.9 张/秒 | 0.60 ms |

两级缓存命中都在 1 ms 以内，说明"L0 先上屏 + L1 空闲补位"在 release 下是够用的。

### 3.2 1 万项实机（冷缓存，`%LOCALAPPDATA%\albumio\thumbs` 已清空）

| 项 | 值 |

| DOM | 48 个瓦片 / 8 行（1 万项） |

### 3.3 与 `01-方案文档.md` §3 预算对照

| 指标 | 目标 | 实测 | 结论 |
| --- | --- | --- | --- |
| 首屏 60 格显示颜色（L0，缓存已建） | ≤ 900 ms | 首屏 48 格全部出 L0 722 ms（**冷缓存**，比目标口径更严） | 达标 |

| 单张 L0 生成 | ≤ 2 ms（只读 JPEG 头与 DC 系数） | 7 ms（当前是分数解码 + 缩放，**未做 DC 直读**） | **未达标**，见 §7 |
| 网格连续滚动 | 60fps 稳定，掉帧率 < 0.5% | 平均 89 fps、p95 14.5 ms、0 帧 >33 ms；以 16.7 ms 为阈值有 41/900 帧超出（4.56%） | 帧率达标、严格阈值未达标，见 §7 |
| 网格 DOM 节点数 | ≤ 300 | 48 瓦片 + 8 行 + 固定外壳，约 120 个节点 | 达标 |
| 滚动时的新缩略图出现 | 无空白格（L0 兜底） | 滚动 10s 后可见区 66/66 出图 | 达标 |

### 3.4 实机问题与修正（本轮）

首轮实机滚动后，新进视口的格子一个 `<img>` 都没有（`imgs 0 / tiles 66`），队列里堆了 2415 个已经滚出视野的任务。原因不是缩略图生成，而是调度：

1. 空闲时 `findIndex(level === "l0" || idle > 120)` 会取到队列里更靠前的 **L1**，2 个 L1 占满 4 个并发槽后，可见格子的 L0 被永久饿死；
2. 滚动跨行只加不减，陈旧任务越堆越多，新任务的位次一直排在后面；
3. blob URL 缓存淘汰时会 `revoke` 仍在屏幕上的图片。

修正（`Browse.tsx` / `source.ts`）：

- L0 严格插在 L1 前面；L0 槽满时才借 L1 的空槽，且 L1 单独限并发 2、滚动中不放 L1；
- 每次可视区变化就丢掉窗口外的排队任务（`thumbQueue` 与 `thumbState` 都按当前窗口裁剪）；
- 缓存淘汰只丢索引不 `revoke`，改由 `releaseThumb` 在缩略图状态被裁剪时归还，避免撤销在屏的 blob URL。

修正后同一场景 66/66 全出图。

### 3.5 dev 编译配置

`cargo test` / `tauri dev` 默认 `dev` 档，图像解码/缩放比 release 慢约 30 倍（L1 单张 22 ms → 约 700 ms），肉眼会误判成前端卡死。已加：

```toml
[profile.dev.package."*"]
opt-level = 3          # 注册表依赖
[profile.dev.package.albumio-core]
opt-level = 3          # 工作区路径依赖要单独点名，`"*"` 不覆盖
```

## 7. 缺口与需要确认的事

1. **Linux WebKitGTK 未实测**：本机无 Linux 环境，S5 与上面的滚动数据都来自 Windows WebView2。已预置四级降级阶梯（`app/docs/spike/S5.md`），M9 打包前在 Linux 实机复测。是否接受"先按 Windows 数据推进、M9 前补测"需要确认。
2. **Delete / Shift+Delete 缺设计**：要二次确认对话框，`design/index.html` 与 `02-设计规范.md` 都没有该界面。按 G2 需要先补设计稿再实现，本里程碑未动。
3. HDD / 网络盘的 S4 数据缺失（本机无介质），现有策略对慢介质是保守的（readdir 先出、stat 按优先级补）。
4. **L0 没有做 DC 直读**：`01-方案文档.md` §3 给的单张 L0 预算是 ≤ 2 ms（只读 JPEG 头与 DC 系数），当前实现是"分数解码 + 缩放"，实测 7 ms。功能上够用（L0 只是占位色块），但预算表这一行目前是欠的，要么在 M3 前补 DC 直读，要么把预算改成与实现一致的 8 ms —— 需要确认走哪条。
5. **滚动掉帧阈值**：本机是 144Hz 面板，以 16.7 ms（60Hz 一帧）为阈值统计有 4.56% 帧超出，但 0 帧 >33 ms、平均 89 fps。这个数字在 60Hz 屏幕上会怎么表现，本机测不出来。建议接受"平均帧率 + 无 >33ms 帧"作为口径，或在一台 60Hz 机器/虚拟机上复测后再定。
