## 2. Windows 本地出包实测

构建：`cd app && npm run tauri build`（release，LTO + strip + opt-level s）。

| 产物 | 字节 | 折算 | 预算（Win ≤ 35MB） |
| --- | --- | --- | --- |
| `albumio.exe` | 6,917,120 | 6.60 MiB | — |
| `albumio_1.0.0-alpha1_x64_en-US.msi` | 3,375,104 | 3.22 MiB | 通过 |
| `albumio_1.0.0-alpha1_x64-setup.exe`（NSIS） | 2,489,853 | 2.37 MiB | 通过 |
| `albumio-1.0.0-alpha1-windows-x64.zip`（portable） | 3,045,523 | 2.90 MiB | 通过 |

两种口径：

- **不含 libheif**：上表即 Windows 口径，远低于 35MB。
- **含 libheif**：macOS/Linux 已按 M9 决策内置 libheif（静态编译，随 dmg/AppImage/deb 分发）；本机无法产出这两类包，增量未实测，需 CI 出包后补记录。Windows 仍走 WIC，不增加体积。

包内校验（不安装、只读查询）：

- MSI `Extension` 表：14 条，`jpg/jpeg/jpe/png/webp/heic/heif/heics/heifs/tif/tiff/bmp/gif/avif` 全部注册到 `albumio.<ext>` ProgId。
- `albumio.exe` 内嵌清单包含 `longPathAware`、Win10/11 `supportedOS`、`Microsoft.Windows.Common-Controls`。

构建期发现并修复：WiX 默认数据库代码页为 1252，中文 `ProgId Description` 会让 `light.exe` 报 `LGHT0311`。关联名称改为 ASCII（`JPEG image` 等），中文产品名与描述不受影响。

## 3. 系统集成逐条

### 3.1 默认打开方式

- Windows：MSI/NSIS 写入 ProgId 与 Extension；Win10/11 的"默认应用"仍由用户在系统设置里选定（UserChoice 哈希保护，安装器不能静默抢占）。
- macOS：`fileAssociations` 写入 `Info.plist` 的 `CFBundleDocumentTypes`；`rank=Alternate` 表示不抢默认。
- Linux：Flatpak 的 `.desktop` 声明 `MimeType`；deb/AppImage 由 Tauri 生成同内容 desktop 文件。

### 3.2 启动参数与拖放

- `albumio <路径>`：目录直接打开；文件打开父目录并在看图里定位该文件（`release_target`）。
- 拖放：整窗接收首个路径，规则同上；非图片扩展名给明确的 Toast，不静默失败。
- 列表尚未返回时先记下目标，等目录列表到齐再定位，避免退化成"打开第一张"。
- 管理员进程收不到 Explorer 的 OLE 拖放（已知平台限制）：启动时检测 TokenElevation，命中则 Toast 明示"请从侧栏进入图片所在目录"。

### 3.2.1 单实例（M9）

- 第二进程由 `tauri-plugin-single-instance` 拦下并立即退出，argv 里第一个真实存在的路径作为目标。
- 已运行的窗口做 `unminimize → show → set_focus`，再通过 `albumio://open-target` 事件把目标交给前端。
- 目标同时写入 `PendingTarget` 槽；前端启动时调 `albumio_take_pending` 取一次（取走即清空），覆盖"前端还没挂上监听"的窗口期，也不会重复打开。
- 没有目标（例如再点一次图标）时只置前，不改变当前目录。

### 3.2.2 剪贴板粘贴（M9）

- Windows：读 CF_HDROP（资源管理器"复制"写的就是这个格式），剪贴板被占用时重试 5 次（每次 20ms），仍失败给可读错误。
- macOS：Finder 复制文件时剪贴板是 furl 列表，用 `osascript` 取 `POSIX path`，免引第三方剪贴板依赖。
- Linux：优先 `wl-paste --type text/uri-list`，回退 `xclip`；都没有时提示"读剪贴板需要 wl-paste 或 xclip"。
- 前端 `Ctrl/Cmd+V`：剪贴板为空给"剪贴板里没有文件"；多于一个文件时打开第一项并提示总数；输入框内的粘贴不受影响（`isTextInput` 放行）。

### 3.3 Win11 右键菜单（MSIX sparse + IExplorerCommand）

目录 `app/windows-shell/`：

- `identity.json`：**唯一**的标识配置（`packageName` / `publisher` / `displayName` / `version` / `applicationId` / `verbId` / `executable` / `dllName` / `clsid`）。当前沿用 `com.albumio.app` 与占位 Publisher `CN=Albumio`，等标识确认后只改这里。
- `src/context_menu.cpp`：`IExplorerCommand` 实现。`GetTitle`="用 Albumio 打开"；`GetState` 只在选中项全是图片时给 `ECS_ENABLED`，否则 `ECS_HIDDEN`（清单里按 `Type="*"` 注册，靠它过滤）；`Invoke` 取第一个选中项的 `SIGDN_FILESYSPATH`，`ShellExecute` 调 DLL 同目录的 `albumio.exe`（应用是单实例，第二个进程会把路径转给已运行窗口）。
- `src/dllmain.cpp`：`DllGetClassObject` / `DllCanUnloadNow` + `IClassFactory`，CLSID 来自生成的 `clsid.h`，与清单同源。
- `AppxManifest.template.xml`：sparse 包清单（`uap10:AllowExternalContent`、`com:SurrogateServer`、`desktop4:FileExplorerContextMenus` + `desktop4:ItemType Type="*"` + `desktop4:Verb`、`runFullTrust`）。
- `build.ps1`（`npm run build:shell`）：读 `identity.json` → 生成 `build/generated/clsid.h` 与 `build/pkg/AppxManifest.xml` → 拷应用图标 → `cl.exe` 编 `build/bin/AlbumioShell.dll` → `MakeAppx pack /nv` 出 `build/AlbumioShell.msix`（未签名）。

踩过的 schema 约束（已修）：`com:Class/@Id` 与 `Verb/@Clsid` 这个 SDK 要**不带花括号**的 GUID；右键菜单必须走 `desktop4:ItemType` 而不是直接把 Verb 挂在 `FileExplorerContextMenus` 下；`EntryPoint="Windows.FullTrustApplication"` 必须配 `rescap:runFullTrust`；sparse 包的 exe 在包外，`MakeAppx` 要加 `/nv` 才不报"清单引用的文件不存在"。

### 3.4 自绘窗口外壳

窗口 `decorations: false`。M9 补齐了标题栏 `data-tauri-drag-region` 与三个窗口按钮的 Tauri 调用；新增 `capabilities/default.json` 授权 `start-dragging/minimize/toggle-maximize/close`。此前按钮没有 onClick、拖拽用的是 Electron 的 `-webkit-app-region`，在 WebView2 下不生效。

## 5. 计划冲突与决策点

1. **右键菜单**：`04-项目计划.md` M9 要求 Win11 右键菜单（MSIX sparse + IExplorerCommand）；`01-方案文档.md` §524 原建议放后续迭代。**已决策：本版交付**。与标识无关的部分已实现（§3.3），标识集中在 `app/windows-shell/identity.json`。
2. **libheif**：已决策内置（macOS/Linux），Windows 保持 WIC；见 §2 与 §6。
3. **单实例 / 剪贴板粘贴**：`01-方案文档.md` §524 列入首版承诺。**已决策：纳入首版**，已实现，见 §3.2.1 / §3.2.2。
4. **identifier**：`com.albumio.app` 以 `.app` 结尾，Tauri 警告与 macOS bundle 扩展名冲突。M0 已定该标识且影响安装升级路径，本轮不动，**需用户决策**是否在签名前调整。

## 8. 已知缺口

1. 三平台签名、公证、装包、冷启动、G3 全部未做（见 §6）。
2. macOS CI 的 universal2 + 公证链路未实际跑过（仅静态接线）。
3. Flatpak 清单按 GNOME 46 编写，未在本机或 CI 构建；SDK 扩展版本可能需按 flathub 实际可用版本调整。
4. 拖放与标题栏窗口动作无 GUI 手测：已通过类型检查与构建，但未在真实窗口里点过。
5. `com.albumio.app` 的 macOS 警告未处理（§5.4）。
6. portable 包不含 WebView2 离线安装器；Win10 缺运行时会打不开（`使用说明.txt` 已写明）。
7. macOS/Linux 的内置 libheif 未在本机编译（Windows 不编译该依赖）；CI 首次出包需确认 cmake/libde265/libwebp 链路与体积增量。
8. 单实例与剪贴板只过了编译：第二实例转发、置前行为、Windows CF_HDROP 读取均未在真实双击/复制粘贴下验证。
9. 剪贴板在 macOS（osascript 取 furl）与 Linux（wl-paste/xclip）未运行过；Linux 还需要系统装有其中之一。
10. 右键菜单未签名、未注册、未在资源管理器里看过：MSIX 必须签名才能 `Add-AppxPackage`；`IExplorerCommand` 的 `GetState`/`Invoke` 只有编译与 COM 入口验证。
11. 右键菜单尚未进入安装器：`AlbumioShell.dll` 需要和 `albumio.exe` 同目录，MSI/NSIS 还没有带它；等标识确定后再接安装器与 CI（CI 出 msix 也需证书才能装）。
