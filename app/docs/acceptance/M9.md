## 2. Windows 本地出包实测

构建：`cd app && npm run tauri build`（release，LTO + strip + opt-level s）。

| `albumio_1.0.0-alpha1_x64-setup.exe`（NSIS） | 2,489,853 | 2.37 MiB | 通过 |
| `albumio-1.0.0-alpha1-windows-x64.zip`（portable） | 3,045,523 | 2.90 MiB | 通过 |

两种口径：

- **不含 libheif**：上表即 Windows 口径，远低于 35MB。
- **含 libheif**：macOS/Linux 已按 M9 决策内置 libheif（静态编译，随 dmg/AppImage/deb 分发）；本机无法产出这两类包，增量未实测，需 CI 出包后补记录。Windows 仍走 WIC，不增加体积。

包内校验（不安装、只读查询）：

- MSI `Extension` 表：14 条，`jpg/jpeg/jpe/png/webp/heic/heif/heics/heifs/tif/tiff/bmp/gif/avif` 全部注册到 `albumio.<ext>` ProgId。
- `albumio.exe` 内嵌清单包含 `longPathAware`、Win10/11 `supportedOS`、`Microsoft.Windows.Common-Controls`。

构建期发现并修复：WiX 默认数据库代码页为 1252，中文 `ProgId Description` 会让 `light.exe` 报 `LGHT0311`。关联名称改为 ASCII（`JPEG image` 等），中文产品名与描述不受影响。

## 3. 系统集成逐条

### 3.1 默认打开方式

- Windows：MSI/NSIS 写入 ProgId 与 Extension；Win10/11 的"默认应用"仍由用户在系统设置里选定（UserChoice 哈希保护，安装器不能静默抢占）。
- macOS：`fileAssociations` 写入 `Info.plist` 的 `CFBundleDocumentTypes`；`rank=Alternate` 表示不抢默认。
- Linux：Flatpak 的 `.desktop` 声明 `MimeType`；deb/AppImage 由 Tauri 生成同内容 desktop 文件。

### 3.2 启动参数与拖放

- `albumio <路径>`：目录直接打开；文件打开父目录并在看图里定位该文件（`release_target`）。
- 拖放：整窗接收首个路径，规则同上；非图片扩展名给明确的 Toast，不静默失败。
- 列表尚未返回时先记下目标，等目录列表到齐再定位，避免退化成"打开第一张"。
- 管理员进程收不到 Explorer 的 OLE 拖放（已知平台限制）：启动时检测 TokenElevation，命中则 Toast 明示"请从侧栏进入图片所在目录"。

### 3.3 自绘窗口外壳

窗口 `decorations: false`。M9 补齐了标题栏 `data-tauri-drag-region` 与三个窗口按钮的 Tauri 调用；新增 `capabilities/default.json` 授权 `start-dragging/minimize/toggle-maximize/close`。此前按钮没有 onClick、拖拽用的是 Electron 的 `-webkit-app-region`，在 WebView2 下不生效。

## 5. 计划冲突与决策点

1. **右键菜单**：`04-项目计划.md` M9 要求 Win11 右键菜单（MSIX sparse + IExplorerCommand）；`01-方案文档.md` §524 原建议放后续迭代。**已决策：本版交付**。先落与标识无关的 COM 工程、IExplorerCommand 与清单/构建脚本，应用标识留一处可替换配置，待确认后一处改完。
2. **libheif**：已决策内置（macOS/Linux），Windows 保持 WIC；见 §2 与 §6。
3. **单实例 / 剪贴板粘贴**：`01-方案文档.md` §524 列入首版承诺。**已决策：纳入首版**，实现见后续提交。
4. **identifier**：`com.albumio.app` 以 `.app` 结尾，Tauri 警告与 macOS bundle 扩展名冲突。M0 已定该标识且影响安装升级路径，本轮不动，**需用户决策**是否在签名前调整。
