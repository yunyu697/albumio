## 3. 差异清单

### 3.1 已消除

- 设计稿 `.winbtn.close:hover{color:#fff}` 是外壳里唯一的色值字面量。已提为 `--lv-winclose-fg: #FFFFFF`（写在 `palette.css`，两套主题共用），取值与设计稿完全相同，**无视觉差异**，目的是守住"palette.css 以外不出现色值"。

### 3.2 结构性差异（设计稿本身声明为非产品界面，不计入偏差）

| 差异 | 原因 |
| --- | --- |
| 实现没有稿子外层 `.specbar`（44px 导航条）与桌面底色 `--lv-desk` | 设计稿注释：`--lv-specbar-h: 44px; /* 仅稿子外层导航，不属于产品界面 */` |
| 实现的 `.app` 无 `inset` / `border-radius` / `elevation-3` 投影 | 同上；产品界面是整窗，圆角与投影由系统窗口决定（Windows 11 圆角由 DWM 提供） |
| 同一 1440 宽下主区宽 920（实现）vs 860（设计稿） | 设计稿的 `.app` 左右各缩进 12px，主区因此少 24px |

### 3.3 范围内留白（M0 不做，后续里程碑补齐）

| 留白 | 归属 |
| --- | --- |
| 侧栏、主区、检查器的内部内容为空容器 | M1（目录树）/ M2（网格）/ M3（检查器） |
| 工具条、分段控件、窗口按钮均无交互 | M1 起逐步接 |
| 状态栏数值为设计稿静态文案 | M2 接真实计数 |
| 键位与键位提示层的交互（延迟、聚焦、`aria-keyshortcuts`） | M2 起按规范 §10.8 分批，M0 只落视觉形态（见 §5.2） |

## 4.1 本里程碑新增、设计稿未覆盖的两处

1. **应用图标**（`src-tauri/icons/icon.png`、`icon.ico`）：设计稿没有图标资产（属 M9 打包范围）。M0 先用品牌标记的几何生成占位：`--ds-color-accent` 底 + 设计稿 `#i-image` 的 24 网格图形 + `--ds-color-on-accent` 描边，不引入新色值。**M9 需要正式图标**。
2. **窗口最小尺寸 432×284**：由 `02-设计规范.md` §2.2.5 解出，已写进 `tauri.conf.json` 的 `minWidth/minHeight`（曾误写 720×480，已废弃；曾写 434，是把设计稿 `border` 的 2px 算进产品坐标，已改为描边环后统一为 432）。

## 6. 需要真实窗口才能判断的项（请自行运行）

headless 无法判断的部分，列成清单，不为了验收弹窗：

1. 无边框窗口下，顶部 48px 的拖拽区是否顺滑；双击标题栏空白处应最大化/还原。
2. 三个窗口按钮（最小化/最大化/关闭）的 hover 与点击是否命中预期区域；关闭键 hover 应变红、图标变白。
3. Windows 11 的窗口圆角与投影是否与设计稿观感一致（DWM 提供的圆角半径不可控，只能看）。
4. 1440×900 与 125% / 150% 显示缩放下，标题栏文字与面包屑是否都不折行。
5. 首次启动后 `%APPDATA%\albumio` 目录是否被创建（`src-tauri/src/lib.rs` 的 `data_dir`）。
6. 冷启动到可见窗口的时间（M0 只记录，不做门槛）。
