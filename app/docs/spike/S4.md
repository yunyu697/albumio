# S4 · 1 万文件目录的 `readdir` 与 `stat` 耗时

- 目的（`04-项目计划.md` §2）：拿到真实耗时，验证"readdir 与 stat 必须分离"是否必要，并给 M2 的 P0–P4 队列定依据。
- 方法：`scripts/spike-s4-files.mjs` 生成 1 万个空文件（JPG/PNG/HEIC 混合），`cargo run --release -p albumio-core --example readdir_bench -- <目录>` 跑 5 轮取中位数。三段分别计时：
  1. `read_dir` 只取名字；
  2. `read_dir` + `DirEntry::file_type()`（判断文件/目录，不做 `stat`）；
  3. `read_dir` + 对每个文件 `fs::metadata`（全量 stat）。
- 复跑命令：

```
node scripts/spike-s4-files.mjs "$env:TEMP\albumio-s4" 10000
cd app/src-tauri
cargo run --release -p albumio-core --example readdir_bench -- "$env:TEMP\albumio-s4"
```

## 实测

介质：本机 NVMe SSD（C:）。本机没有 HDD 与网络盘挂载点（`Get-PSDrive` 只有 C–G 本地盘），因此 HDD / 网络盘一档**未实测**，见"限制"。

| 阶段 | 中位数 | 相对 readdir |
| --- | --- | --- |
| readdir 仅名字（10000 条） | 5.60 ms | 1× |
| readdir + `file_type` | 8.52 ms | 1.5× |
| readdir + 全量 stat | 835.51 ms | 149× |

## 结论

1. **必须分离**：名字与目录/文件类型 8.5 ms 拿全，全量 stat 要 835 ms。若"进目录先 stat 全部再显示"，首屏会多等 0.8 秒，是 150 倍差距，不是优化问题而是结构问题。
2. **P0 只 stat 可见区**：一屏 24–40 格，按每格 ~0.08 ms 计约 2–3 ms，可在一帧内完成；再叠加缩略图解码才是主要成本，因此 stat 不能跟缩略图绑在一起。
3. **P2/P3/P4 必须有 generation 取消**：835 ms 的全量 stat 期间用户可能已经换目录，旧结果必须整批丢弃（M2 的 generation token）。
4. 网格首屏的数据路径定为：`albumio_list`（readdir，仅名字 + 是否目录，5.6 ms 量级）→ 立即出格子占位 → 按 P0/P1 分批 `albumio_stat_batch` → L0 上屏 → L1 补位。

## 限制与后续

- HDD / 网络盘未实测：本机无对应介质。分离策略对介质差异是**保守**的（readdir 先出，stat 按优先级补），不依赖 HDD/网络盘的绝对值。
- M2 验收时会用真实 1 万文件目录复测"进目录 → 首屏可用"的端到端耗时，与本页的 8.5 / 835 ms 对照。
  - 已复测（`app/docs/acceptance/M2.md` §3.2）：冷缓存下首屏 48 格 L0 全出 722 ms，首屏可用不受 835 ms 全量 stat 影响，分离策略成立。
