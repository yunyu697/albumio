# S2 · 三平台 HEIC 解码可用性

- 目的（`04-项目计划.md` §2）：确认 HEIC 在哪些平台必须内置 libheif，决定 M1 的 HEIC 分支与 M9 的包体预算。
- 方法：清点本机 Windows 11（26100 系）上的系统 HEIC 能力；macOS / Linux 无法在本机实测，按平台事实记录并标注未实测。

## 实测（Windows）

| 项 | 结果 |
| --- | --- |
| `Microsoft.HEIFImageExtension` | 已安装，1.2.62.0 |
| `Microsoft.HEVCVideoExtension` | 已安装，2.5.48.0 |
| 系统 WIC 是否具备 HEIC 解码 | 具备（HEIF 扩展 + HEVC 扩展同时存在才可解 HEVC 编码的 HEIC） |

关键事实：**HEVC 扩展在 Windows 上不是默认预装**（Microsoft Store 付费/可选组件），HEIF 扩展也只是随照片应用附带。同型号的干净系统很可能只有 HEIF 扩展而无 HEVC 扩展，此时 HEIC 只能读出缩略图以外的容器信息，主图解码失败。

## 结论

| 平台 | 系统 codec | 判定 |
| --- | --- | --- |
| Windows | 依赖两个 Store 包，不保证存在 | **必须内置 libheif 兜底**；系统 codec 只作可选加速 |
| macOS | ImageIO 原生支持 HEIC | 可用系统 codec，不内置 |
| Linux | 无系统级 HEIC | **必须内置 libheif** |

- 计划 §5 R1 的"接受 +6–8MB 内置 libheif"由此确认。
- 未实测项：macOS / Linux 的实际解码结果与色彩一致性，随 M9 的平台机实测补齐；不影响 M1 的链路设计（M1 的 HEIC 分支只做"有 decoder 就用，没有就返回可判定的 `Unsupported`"，不让 UI 静默失败）。

## 对 M1 的影响

1. 格式探测必须识别 HEIC（`ftyp` 品牌：`heic/heix/hevc/hevx/mif1`），即使本机无解码器也要给出正确格式而不是"未知文件"。
2. 解码器缺失时返回带原因的 `Unsupported { format, reason }`，由 UI 显示占位与提示；不 panic、不返回空图。
3. libheif 的静态链接与包体实测归 M9；M1 不引入系统级 C 依赖，保持 `cargo test` 在三平台可跑。
