# S3 · WebView 的 ICC / 广色域一致性

- 目的（`04-项目计划.md` §2）：确认"只在 Rust 转 sRGB、WebView 只显示 sRGB"这条决策成立。
- 方法：Edge headless 页面把 8 个已知 sRGB 色块绘到 canvas → 编码为无损 PNG 与 q80 WebP → 重新解码绘制 → 逐像素与源比较。若 WebView 对"未打 ICC 的输出"按 sRGB 解释，则颜色必须原样返回。

## 实测

| 编码 | 体积 | 最大通道偏差 | 平均偏差 |
| --- | --- | --- | --- |
| PNG（无损） | 222 B | 0 | 0 |
| WebP q80（未打 ICC） | 827 B | 96 | 6.53 |

- PNG 零偏差 → **未打 ICC 的输出被当作 sRGB 解释**，链路假设成立；WebView 不会对无标签图像做隐式转换。
- WebP q80 的偏差来自有损压缩的 4:2:0 色度下采样（8px 硬边处最明显），不是色彩管理问题。

## 结论

1. 决策成立：转换在 Rust（lcms2）一次完成，输出**不带 ICC** 的 sRGB WebP；WebView 侧的 ICC 行为不参与成像结果。
2. 新增一条实现要求：缩略图编码启用 libwebp 的 `sharp_yuv`（锐化色度），减少硬边彩边；这属于编码参数，不改格式与质量档。
3. 未实测项：macOS WKWebView 与 Linux WebKitGTK 的缩放/合成色域行为。由于我们输出无标签 sRGB，二者也应按 sRGB 解释；随 M9 平台机复核。

## 对 M1 的影响

- 管线出口固定为"sRGB、无 ICC 标签"的 WebP；从原图读到的 ICC 只在解码→缩放之后、编码之前使用一次。
- 编码参数：L1/L2 用 q80 + `sharp_yuv`；L0 用无损（32px，体积 < 1KB）。
